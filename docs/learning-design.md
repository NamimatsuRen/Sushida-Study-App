# 学習モード v0.5：設計・実装・検証

## 目的

写すタイピングから、意味・場面を手掛かりに英語を生成する学習へ進む。寿司打風の画面とテンポを保ち、ユーザー提案の頭文字・段階ヒント・締め切りを統合する。楽しい完答と、長期に取り出せたことは分けて扱う。研究の詳細と限界は [調査メモ](research/learning-evidence.md)。

## 3コースと教材

| コース | 学ぶ単位 | 例 | コース時間 / お皿の期限 |
| --- | --- | --- | --- |
| お手軽 | 単語 | decision | 60秒 / 3秒 |
| お勧め | 熟語・コロケーション | make a decision | 90秒 / 5秒 |
| 高級 | 例文 | i need to make a decision | 120秒 / 10秒 |

同じ12テーマを3段階、計36問用意。各段階の項目ID・復習履歴は別に持つ。お手軽で正解しても高級の間隔は進まない。時間や題数は継続しやすさを試す初期値であり、研究の最適値ではない。

## 体験

1. タイトルの「学んで遊ぶ」から学習メニューへ。「タイピングだけで遊ぶ」から既存のゲームにも入れる。
2. 期限が来たカード→未学習→期限前の追加練習の順で出題。固定の枚数終了・新規の日次制限を外し、制限時間まで周回する。実際に出題した新規カードだけを導入済みとして保存。
3. 初見の答え一覧は折りたたみで任意。すぐ始めて段階ヒントを頼りに覚えることも、先に確認することもできる。
4. 問いが表示されたら、頭文字と文字数から取り出す。`a____` で `a` を打ち、次の位置を2回ミスすると `ap___`。表示しても入力位置は進まず、`p` を打って初めて進む。
5. 合う文字を1文字ずつ受理し、最後まで打てば自動判定。ミスは入力欄に残さず、Backspace不要。手動で「次の1文字」や「答えを見る」も選べる。
6. 追加ヒントなしの正解では直ちに次へ。ヒント付き完答は250ms、答えの開示・時間切れは900msだけ答えを見せて自動で次へ進む。Enter/Spaceや「すぐ次へ」で早送りでき、「止めて確認する」で保留できる。長い解説は結果画面へ集約。自動フィードバック中もコース時計を進める。「止めて確認する」を選んだときだけ停止する。
7. 復習予定を保存。失敗・ヒント追加は、2問挟める場合にその直後へ1回再挿入。1周したら次の周回へ入り、2周目以降は全てextra（追加練習）。解き直しや周回だけで長期の間隔を延ばさない。
8. 「手掛かりなしで確認」を選ぶと、頭文字・文字数・入力途中の正誤を見せず、全文を入力してEnterで判定する。通常の支援付き練習と別に集計。

## ヒントと判定

- 標準の頭文字・空白・文字数は初めからの手掛かりであり、これで完答しても完全な自由再生とは呼ばない。
- 同じ入力位置で2回ミスするとその文字を追加開示する。正しい文字を打つと、その位置のミス回数をリセット。
- 開示済みの頭文字を誤入力しても、追加の情報は出ない。追加ヒント数にも加えない。
- 追加の文字を一度でも見れば、最終的に完答しても `assisted`。ヒント後の完答を `recalled` に戻さない。
- 初回の受理文字は、大文字小文字・全角半角を正規化して比較。登録した別解も受理可能。候補が切り替わると表示する長さも候補に合わせる。
- 手掛かりなし確認は `testAnswer()` で全文判定し、部分入力に正誤を返さない。誤答・答えの開示・時間切れは `forgot`。
- 2回ミスの閾値はユーザーのアイデアを実験可能な仕様にしたもの。学習効果が実証済みとは表示しない。

## 時間と動機

- コース時計は回答中と自動フィードバック中に進む。皿の時計は回答中のみ。開始前の確認・結果解説・明示的な保留・ダイアログ・一時停止・他タブへの離脱中はどちらも止める。
- 皿の期限で今のカードを学び直しへ回す。コース時間が尽きたら、今の答えを短く表示して結果へ。未回答カードを失敗と数えない。
- 入力する英語の正規化後の文字数で価格を決める。4字まで100円、5–7字180円、8–14字240円、15–24字380円、25字以上500円。空白も1文字に数える。初回・復習・周回・ヒント付きのいずれも、完答は価格全額、未完答・答えの開示・時間切れは0円。失敗には罰金を付けない。
- 金額は演出であり、記憶量や保持率の単位ではない。学習の金額を既存タイピングの自己ベストや元取りランキングに混ぜない。
- 250ms/900msはテンポを試すUIの仮設定。短い表示だけで十分に学べるという主張ではなく、詳細な解説は終了後に任意で読む。
- 締め切りでやる気が上がる可能性と、考える前にヒントへ頼る可能性の両方を検証する。

## 保存とスケジュール

`localStorage['sushi-type-learning-v1']` に保存し、旧タイピング／暗記版のキーは変更しない。

- progress：項目ごとの `introducedAt`, `lastReviewedAt`, `due`, `stage`, `attempts`, `successes`, `lapses`。
- logs：直近2,000回答。`id`, `at`, `kind`, `cue`, `outcome`, `addedHints`, `misses`, `timedOut`, `delayed`, `points`。入力した生の回答文はログに保存しない。
- kind：`new`, `review`, `retry`, `extra`。cue：`initial-and-length` / `none`。
- outcome：`recalled` は**追加ヒントなしの完答**であり、cueの値を必ず一緒に解釈する。`assisted` は追加文字ヒント付き、`forgot` は未完答・答え開示・時間切れ。
- 成功して期限が来ていれば1→3→7→14→30→60日。ヒント追加・失敗は10分後に再学習、段階を0へ。初回の成功も1日後から確認する。
- 解き直しと期限前の追加練習は、成功・失敗のどちらでも元の復習予定を保持。
- 出題前の新規カードは導入済みにしない。中断後に残りの新規項目を失敗扱いしない。
- 未回答で中断した初回カードは「後日復習」と誤認せず、次回も初回練習として扱う。
- 不正な保存値はスケジュール計算前に除外。保存に失敗したら通知する。ブラウザ削除で記録が消え、端末間同期やバックアップ復元は未実装。

上記は透明な簡易方式で、FSRSの記憶モデル・最適化・目標保持率は実装していない。

## 測るもの

| 指標 | 対象 | 意味・限界 |
| --- | --- | --- |
| 追加ヒントなし完答 | 頭文字・文字数がある通常課題 | 手掛かりを使った想起の成績。完全な自由再生ではない |
| 追加ヒント数 | 文字を追加した回答 | 手助けが減ってきたかを確認する材料 |
| 手掛かりなし後日正答 | cue=none、期限が来た復習、前回から20時間以上かつ日付が異なる | 後日取り出せたかの記録。会話への一般化までは測れない |
| 頭文字付き後日完答 | 同じ遅延条件、cue=initial-and-length | 自由再生と別の分母に集計 |
| 楽しさ・負荷 | 今後のユーザーテスト | 続けたいか、締め切りが急かし過ぎないか |

初回の直後、同じ回の再挑戦、期限前追加練習を「後日正答」の分母に入れない。20時間という区切りも実装上の運用定義で、研究の標準値ではない。結果画面では挑戦回数と異なる問題の種類数を分ける。通常の周回は挑戦回数へ含み、間違い直後の再挑戦は通常成績へ二重計上しない。問題ごとの答え・例文・解説は1種類につき1つにまとめる。推定の記憶保持率や習得済み表示は出さない。

## Markdown登録

1つの自分用デッキを保存する。`#` がデッキ名、`##` が問い、`答え:` は必須、`解説:` は任意。別解は `|` 区切り。最大100枚、ファイル100KB、問題400字・答え200字・解説1,000字以内。全項目は1行ずつ。

内容のIDは問題と答えから作る。同じ問題・答えの説明を直しても復習記録を保持。問題・答えを変えれば新規カード。HTMLを解釈せず、表示時はエスケープする。日本語回答にも対応する。単語から熟語・例文を自動生成する機能はなく、自分で問いを登録する。

## 今回の受け入れ検証

- Appleの例：`a____` → `a` → 2回誤答 → `ap___`。入力位置は1のまま。
- その後完答しても追加ヒントありで保存、10分後の復習へ。
- 文字のヒント、正しい文字を打った後のミス数のリセット、別解、時間境界をモデルで検証。
- コース時計・皿時計、自動フィードバック中のコース時計の継続、保留・ヘルプ・タブ離脱中の停止をDOMで検証。
- 後日正答の分母、レベル間の独立、初回・解き直し・追加練習の除外を検証。
- Markdownの不正入力、スクリプトの無害化、説明変更時の履歴維持を検証。
- 正解直後の自動進行、周回時のextra分類、固定枚数を超える出題、2問後の再挿入、自動進行中の保留・タブ離脱・画面変更を検証。
- 既存のタイピングゲームのテストも維持。

対応するブラウザQAツールがないため、実ブラウザの見た目・実機IME・音・タッチ操作の検証は未実施。

## 次の小さな検証

1. 同じ難度の未学習項目を2群に分け、表示文のタイピングと現在の頭文字付き練習を、学習時間をそろえて比較する。
2. 翌日・7日後に、手掛かりなしの日本語→英語と、練習にない文脈で確認する。教材差・順序を入れ替え、結果を強く一般化しない。
3. その間に、時間切れの割合・追加文字数・途中離脱・楽しさを確認する。
4. 学習時間やヒントへの依存が増えた割に後日正答が変わらなければ、締め切りやヒント量を修正する。
5. 復習記録が集まった段階でFSRS導入、頭文字を徐々に減らす方式、音声・自由作文・新規文脈への転移課題を検討する。

## v0.4での判断

ユーザーの「1問ずつ丁寧に確認するより、テンポよく多く回したい」というフィードバックを優先し、固定枚数・新規上限・回答ごとの確認クリックを撤去。短期の周回は練習として扱い、後日の保持と混同しない。復習負荷の制御は今回「時間で区切る」形に変え、研究が大量反復を無条件に支持すると解釈したわけではない。

## v0.5：締め切り感・価格・クリック音

ユーザーの「皿が遅い」「文字数ごとに価値を変えたい」「押した感じが欲しい」に対応。

- コース全体は `core.js` の60/90/120秒を共有し、定義がずれないようにした。1皿は25/35/50秒から5/6/7秒へ短縮。
- 皿の移動は右端の画面外から左端の画面外まで。残り時間に連動し、期限ぴったりでレーン外へ到達する。残り秒数は小数1桁、2秒以下は強調。
- 自動の答え表示中も総時間を進め、待ち時間によってプレイ時間が膨らまないようにした。保留と明示的な一時停止は利用可能。
- 価格は100/180/240/380/500円。皿に額と色を表示し、長い答えほど高額。登録された別解に切り替わった場合も、その答えの文字数で表示・獲得額をそろえる。
- 手掛かりなしの確認では、価格や皿の色から文字数帯が分からないよう、回答前は「完答で加算」と共通色だけを表示。
- 記憶の判定（追加ヒントの有無など）と金額は分離し、ヒントを使った完答でも皿の額を得る。
- 最初のスタート操作、動的に生成したコース選択や設定のボタンにも45msのクリック音。ユーザー操作でAudioContextを開始・再開してから鳴らす。サウンドOFF、無効ボタン、独自の打鍵音がある画面キーボードは対象外。

参考：[公式の中心ルール](https://sushida.net/)、[コース時間の紹介](https://freesoft-100.com/review/sushida.php)、[価格帯と文字数の観察記事](https://www.pc-memo-kids.com/sushida)。公開説明だけでは1皿の厳密な速度式は確認できなかった。上記の皿時間と英語の文字数境界は英語版の調整値であり、本家の内部式や日本語文字数の区分をそのまま複製してはいない。価格・期限はゲーム上の難度の設定で、科学的に最適な学習時間の主張ではない。

## 1皿の時間の調整（v0.5.1）

ユーザー指定に合わせ、単語3秒・フレーズ5秒・例文10秒へ変更。コース全体の60/90/120秒、価格、ヒントと復習の扱いは維持する。
