# FSRSによる復習スケジュール（v0.8）

## 変更内容

## 記憶モデルと間隔

カードごとに、記憶の安定度（stability）、難しさ（difficulty）、前回の復習時刻、学習状態、復習回数などを保持する。前回から経過した時間と今回の評価を `scheduler.next()` へ渡し、次のモデル状態と復習期限を保存する。

FSRS-6の忘却曲線は概略 `R(t) = (1 + factor × t / stability)^decay`。既定の21パラメーターからdecayとfactorを決め、目標保持率に合う間隔を計算する。成功・失敗に応じた安定度や難しさの更新、短期学習の処理も上流実装が行う。

| 設定 | 採用値 |
| --- | --- |
| モデル | FSRS-6、ライブラリ既定の21パラメーター |
| 目標保持率 | 0.90 |
| 最大間隔 | 36,500日 |
| ランダムな間隔の分散（fuzz） | OFF |
| 短期学習モデル | ON |
| 初回の学び直し・再学習のステップ | 10分 |

たとえば既定の新規カードをGoodで完答すると約2日後、その期限で再びGoodなら約11日後になる。同じ2回目の成功でも、実際に10日空いていれば約25日後になる。これは固定の段階表ではなく、入力した履歴に対するモデルの計算例である。失敗後の10分は、本アプリで明示した短期学習ステップ。

## ゲームの回答から評価へ

| 回答結果 | FSRSへの評価 | 条件 |
| --- | --- | --- |
| 追加ヒントなしで完答 | Good（3） | 初回、または期限の来た復習 |
| 追加文字ヒントを使って完答 | Again（1） | 同上 |
| 答え開示・時間切れ・確認課題の誤答 | Again（1） | 同上 |
| 同じ回の解き直し・期限前の追加練習 | 評価しない | 予定・記憶モデル・復習用カウンターを維持 |

忘れたのにHardを使うと成功扱いになるため、ヒント付き完答をHardにはしない。速度からEasyやHardを推定せず、自己評価ボタンも追加しない。回答ごとの確認待ちを増やさず、従来の即時遷移を保つ。古い出題計画や時計の巻き戻りによる期限前の二重評価も防ぐ。

期限の早い復習→未学習→期限前の追加練習の順で出題。準備画面で待つ間に期限が来る場合に備え、開始時にも出題計画を更新する。単語3秒・フレーズ5秒・例文10秒、コース時間、金額、ヒント、音・ゲージは維持する。

## 保存と既存データの移行

保存キーは `sushi-type-learning-v1` のまま、形式を `version: 3` へ更新する。

- 各progressの `fsrs` に、エンジン・ライブラリ版とモデル状態を保存。時刻はミリ秒の数値とし、外側の `due` をモデルの期限と同期する。
- 評価したログには `scheduled: true`, `rating`, `scheduler`, `nextDue`, `fsrsLog` を保存。追加練習などは `scheduled: false` とし、後日の成績集計にも誤って入れない。
- 正常なFSRS状態はそのまま復元し、再読み込みだけで再計算しない。
- 旧形式で予定更新に使った全回答が残っている場合は、その履歴だけを時系列に再生してモデル状態を作る。解き直し・追加練習は混ぜない。
- ログ上限などで履歴が欠けている場合は、旧stageから安定度を推測しない。既存の期限と累計を保持し、次回の予定された回答から新しい記憶モデルを始める。
- 移行時には既存の復習期限を一斉に変更しない。次の回答からFSRSが新しい期限を計算する。カレンダーの日別合計・Markdownデッキ・過去ログも保持する。
- 不正なモデル状態はカードごとに再構成する。既存の有効な期限・回答累計を捨てず、他の正常なカードにも影響させない。

## 検証と限界

FSRS-6の既定値による計算例、経過時間で変わる間隔、Againの10分、JSON復元、期限順、旧履歴の完全／不完全な場合、破損した状態の復元、重複評価の防止を自動テストする。DOMでも実際の完答→FSRS更新→保存→再読み込みと、準備中に期限が来る場合を確認する。

パラメーターの個人別最適化、Ankiとの同期、端末間同期は未実装。90%はモデルが目指す予測値で、ゲーム中の実際の正答率やヒントなしの長期保持を保証しない。頭文字や時間制限があるため、Ankiの自己評価と同じ測定条件ではない。手掛かりなしの後日確認は、引き続き別に集計する。実ブラウザ・実機での操作確認は未実施。

依存更新時は `npm ci` → `npm run vendor:fsrs` → `npm test` → `npm run check`。通常は追跡済みの `dist/` をそのまま配信できる。`check` は同梱ソースとライセンスが固定パッケージに一致することも検証する。
