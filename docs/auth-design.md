# Google・メール認証と利用者別の記録（v0.9）

ユーザー指定に合わせ、Supabase Authを使う。公開ページはSitesの静的配信、パスワード・Google OAuth・セッションはSupabaseが管理する。ChatGPTアカウントは不要。認証サービスを新しく自作したり、ブラウザ内の名前だけでログインしたことにはしない。

## 実装

| ファイル | 役割 |
| --- | --- |
| `dist/config.js` | Project URLと公開キーのみ |
| `dist/bootstrap.js` | 認証・アカウントの読み込み後にゲームを開始 |
| `dist/auth.js` | PKCE、Google・メール、確認メール、再設定、ログアウト、DBへのアクセス |
| `dist/account-store.js` | ゲスト・利用者別の保存、端末キャッシュ、同期と競合検出 |
| `dist/auth-ui.js` | ログイン・新規登録・再設定・アカウント画面 |
| `supabase/migrations/202611050001_profiles.sql` | 利用者所有のテーブル、RLS、更新時刻 |

GoogleはSDKでPKCEの認証URLを生成し、トップレベルのナビゲーションで開始する。Google側の設定が未完了の場合は、エラーページへ移動する前にアプリ内で案内する。メールはパスワードでログインし、登録時の確認・再設定はSupabaseのメール経由で行う。アプリの学習記録にはパスワードや認証トークンを保存しない。

## データの分離

- ゲストは従来の2つのブラウザ保存キーを使い続ける。
- ログイン後はSupabaseセッションのuser IDを利用し、`sushi_profiles`の自分の行だけを読み書きする。
- DBはRLSを有効にし、未ログインのテーブル権限を外す。認証済みでも `auth.uid() = user_id` の行だけを許可する。公開キーだけで他人の記録を読むことは許可しない。
- 自作問題・FSRS・日別合計・直近回答・タイピングの成績と設定を保存する。認証SDKのトークン用ストレージや、無関係なキーはアップロード対象に含めない。
- アカウントごとの端末キャッシュを分ける。初回のゲスト記録は自動では割り当てず、アカウント画面で本人が引き継ぐ。アカウントに既存の記録がある場合は置き換えない。

## 同期

回答の保存は端末側で即座に反映し、約750msでまとめて送る。ゲーム進行は通信を待たない。初回起動は認証・クラウドの記録を確認してからゲームを読み込み、他の利用者やゲストの記録を混ぜない。

各行にrevisionを持たせる。保存は読み込んだrevisionに一致する場合だけ更新し、複数端末の後の更新が先の更新を黙って消さないようにする。保存中に回答が増えたら、次の版へ続けて保存する。ネットワーク障害時の未同期分は端末に保持し、再読み込み後も再試行できる。

競合では自動上書きを止める。アカウント画面で未同期データをダウンロードし、端末にも退避してからクラウドの版へ戻せる。「記録を同期してホームへ」でアプリを読み直し、画面内の古いモデルが新しいクラウド記録を上書きしないようにする。単純な最終更新時刻だけの上書きや、集計の二重加算を伴う自動マージは行わない。

## 設定と検証範囲

接続先・公開キーは設定済み。SQL・Googleプロバイダー・メール送信設定は所有者から完了の確認を受けている。移行時は管理者が[接続手順](auth-setup.md)に従ってSQL、Googleプロバイダー、メール送信・戻り先を設定する。公開キーでは管理設定を変更できない。秘密情報はGoogle / Supabaseの管理画面へ直接入力する。

自動テストは認証APIの呼び分け・PKCE・失敗時の表示・再設定・ログアウト・利用者別キャッシュ・引き継ぎ・保存競合・オフラインからの復帰・更新中の追加回答を確認する。テストはモックで行い、実際のGoogle認証・確認メール・SupabaseのRLS実行は別途確認が必要。管理画面操作用のブラウザツールは利用できず、実行環境からSupabaseへの接続もネットワーク制限で確認できていない。ゲームの実機見た目・IME・音も未検証。

参考：[Supabase Google認証](https://supabase.com/docs/guides/auth/social-sign-in/auth-google)、[パスワード認証](https://supabase.com/docs/guides/auth/passwords)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。
