# 今後の開発候補

ユーザーの開発案と実装状況を記録。育成要素は構想段階で、細かな仕様は今後検討する。

## ログイン機能

- v0.9でGoogle・メール認証のアプリ側を実装。Supabase Authを利用する。
- 学習記録・FSRS・自作問題・タイピング記録を利用者ごとに保存し、他の端末で読み込む。
- 端末のゲスト記録を残して引き継ぐ操作、保存競合の検出・退避・再読み込みに対応。
- Supabase側のテーブル・Googleプロバイダー・SMTPは所有者確認で設定完了。実際の認証動作は公開先で確認する。[接続手順](auth-setup.md)を参照。

## 元の学習アプリ：単語の登録を「意味のセット」へ

難語を登録し、その意味を伝えるやさしい表現から練習して、難語・その語を使う文章へつなげる案。[登録画面・出題順・復習の設計案](meaning-set-design.md)に整理した。

- 難語・語義・やさしい言い換え・使う場面・例文を1セットにする。
- 初期入力は難語と任意の出典文。やさしい表現と例文の候補を提案・編集する登録画面を考える。
- やさしく言う → 対象の難語に言い換える → 文の中で使う、という順で出題を広げる。
- 段階ごとのFSRS状態を分け、同じ場の成功と後日の想起を区別する。解放条件や自動生成は未実装の設計案。

### AIによる学習セットの生成

AI機能を必須の方向性として、[Geminiによる登録・前提用法・解放条件・接続の設計](ai-vocabulary-design.md)を追加。まだ未実装。

- take・have・goなどは用法単位で扱う。難語を登録したら、その意味に必要な基本表現を提案する。既に使える用法は繰り返し要求しない。
- 基本の言い方 → 対象表現 → 文での使用を3コースに対応させる案。語彙の難しさと入力文字数を分ける。
- AIは登録時に教材を生成。学習済みや次段階の解放は、手掛かり条件・後日の想起などの学習記録で判定する。
- Gemini Flash系を候補とし、既存SupabaseのEdge Functionから接続する。秘密キーは関数側のSecretsで管理する。

### 『5分間英単語』を起点にした基礎学習

[公開資料の調査と設計案](foundation-book-plan.md)を追加。ユーザー案は「本の表現をクリアしてから発展語を追加する」。基礎を優先し、関連用法の習得に合わせて発展へ進む方式も検討する。

- 覚える対象用法と、例文に登場する周辺語を分ける。難しい周辺語には意味表示などの補助を用意する。
- 名詞も、組み合わせの中心なら学習対象にする。品詞だけで一律に除外しない。
- 語の保存と学習開始の解放を分ける案。登録制限の方式は未決定で、現在の登録操作は変更しない。
- 写真取り込み・教材追加・解放は未実装。最初は少数の用法で、対象表現を後日も取り出せるか試す。

## 育成要素：住民が増え、村ができていく

**構想段階。** 住民が増えていき、増えた住民が村を作るような体験を目指す。

- 学習の積み重ねを、住民の増加や村の発展につなげる案を検討する。
- 住民の見た目・役割、家や施設など、村が育っていく表現は未決定。
- 住民が増える条件や発展の速度も、まだ固定しない。
- 現在の学習テンポを保ち、成果をメニューや終了後に楽しめる形を検討する。

育成の最初の試作範囲は今後決める。

## 育成要素：タイピングで稼ぎ、好きな対象を育てる

**構想段階。** 現在の「タイピングで寿司を食べる」体験から、「タイピングでお金を稼ぐ」方式へ広げる案。

### 基本のループ

**タイピングで稼ぐ → 魚などを買う → 育てる**

- 稼いだゲーム内通貨を、育成対象の購入につなげる。
- 最初のイメージは水族館。魚を買い、育てていく体験を考える。
- 学習を続ける理由として、育てる楽しさや変化を見る楽しさを取り入れる。

### 育てる対象をユーザーが選ぶ

- 魚だけに固定しない。
- ほかの生き物や、意味のわからないおじさんのような変わったキャラクターも候補にする。
- ユーザーが好きな育成対象を選べる方式を検討する。

### 生き物が増えると、来場者も増える

- 水族館にいる生き物が増えるほど、お客さんがたくさん来る仕組みを考える。
- 育成の結果が、館のにぎわいとしても見えるようにする。
- 来場者を収益や次の育成へどうつなげるかは、今後検討する。

### 学習の特徴で、ユーザーごとに違う水族館へ

**「学び方が、水族館の個性になる」イメージ。** 複数のパラメーターの組み合わせから、それぞれ異なる館が育っていく案。

| パラメーター候補 | 捉えたい特徴 |
| --- | --- |
| タイピングのミス数・ミス率 | 入力の正確さ |
| タイピング速度 | 入力の速さ・テンポ |
| 新しい表現を覚えているか | 新しく学んだ表現と、その後に思い出せた状況 |

- 生き物の種類・構成、見た目や動き、水槽などに、学習の特徴を反映する案を考える。
- 初回の完答と、後日に思い出せたことは区別する。既存のヒント使用・復習の記録とのつなぎ方も検討する。
- 各パラメーターがどの育成結果に結びつくか、数式や閾値はまだ決めない。

### 来場者もカオスにする

- 観に来るお客さんは、人だけに限定しない。動物・魚・宇宙人・ロボットなども候補にする。
- おじさん・おばさんの比率など、館ごとのキャラクター構成も個性として変わっていく案。
- **館に住む生き物・キャラクターと、それを観に来る客層の両方**が、ユーザーごとに異なる世界を目指す。
- 育てる対象の選択、学習パラメーター、展示側と来場者側の構成をどう連動させるかは、今後検討する。

### 既存の案との関係と未決事項

- 「住民が増えて村を作る」案も残す。水族館・村・キャラクター育成をどう組み合わせるかは未決定。
- 通貨の獲得条件、購入価格、成長の仕組み、対象の選択方法はまだ固定しない。
- 現在の皿の金額はプレイのスコア。育成に使う所持金の保存・購入・成長機能は今後の設計対象。
- FSRSの復習記録と育成報酬の関係を整理し、現在の学習テンポを保てる形を考える。

## 単体プロトタイプ：へんてこ水族館

初期の育成ループを[独立した単体アプリ](../experiments/typequarium-lab/README.md)として試作。試用URLは https://typequarium-ren-lab.namimatsuren.chatgpt.site （所有者限定）。

- 20秒のタイピングでコインを稼ぎ、9種類の仲間から選んで迎える。ごはんで成長し、仲間の数・種類・成長などで客足が増える。
- 正確さ・速度・思い出しチェック、おじさん／マダムの在館比率などで、水・泳ぎ・育ちやすさ・客層が変わる。
- 人・動物・魚・宇宙人・ロボットなどの来場者が混ざる。
- 保存・書き出し・読み込みに対応。本体のログイン・学習データ・FSRSとは連携しない。
- 価格や個性のルールは試作の仮設定。思い出しチェックは同試作内の確認で、長期定着の評価ではない。本体への統合は今後検討する。
