# 単語登録の案：やさしい言い換えから、難語を使える形へ

設計案。元の寿司タイプ向けの次の検討項目であり、この文書ではアプリの登録・出題処理は変更していない。

AIを使う登録・基本語の用法ごとの記録・3コースとの対応・GeminiとSupabaseの接続案は、[AIによる登録の設計](ai-vocabulary-design.md)に具体化した。

## 登録の中心を「同じ意味のまとまり」にする

覚えたい難語、その意味を伝えるやさしい表現、自分が使う場面を1つのセットとして扱う。目指すのは、その内容を身近な英語でも説明でき、必要に応じて難しい表現も選べること。

例として `exacerbate` を使う。ここでは「問題・悪い状況をさらに悪化させる」という語義に限定する。例文はこの案のために作成したもの。英検の公式語彙リストに含まれるという主張ではない。

| セットの要素 | 例 |
| --- | --- |
| 覚えたい語 | exacerbate |
| 伝えたい意味 | 問題や悪い状況を、さらに悪化させる |
| やさしい表現 | make things worse / make the problem worse |
| 使う場面 | 寝不足で、もともとの問題がさらに悪化する |
| やさしい例文 | Not getting enough sleep can make the problem worse. |
| 難語を使う例文 | Lack of sleep can exacerbate the problem. |
| 使い方メモ | exacerbate a problem / a crisis / symptoms など。問題や悪い状態をさらに悪くする。 |

やさしい表現と難語は、あらゆる場面で置き換えられるとは扱わない。単語に複数の意味がある場合は語義を選び、場面・品詞・文型・語感が合う組み合わせを作る。

## 登録の負担を小さくする

基本の入力は「覚えたい単語」。出会った一文を任意で足し、語義が曖昧なら今回覚える意味を選ぶ。ユーザーが毎回すべての例文を書く前提にはしない。

```text
覚えたい単語       [ exacerbate                    ]
出会った一文       [ 任意：記事・本などの一文       ]
使いたい場面       [ 日常 / 仕事 / 試験 / 自分で入力 ]

                   [ 学習セットの候補を作る ]

今回の意味         問題・悪い状況をさらに悪化させる
やさしい言い方     make things worse
やさしい例文       ...
難語を使う例文     ...
別解・使い方       ...

                   [ 編集 ] [ このセットを登録 ]
```

候補の生成は今後実装する機能。生成AIを使う場合も提案として表示し、今回の語義と例文が合うかを確認・修正できるようにする。現在の公開キーだけで文章生成が動くわけではなく、モデル・接続・費用の設計は別途必要。最初の試作は少数の編集可能なセットで体験を確認できる。

目標の「英検1級」はセットのタグとして持たせる。試験級の選択だけで、その級の全語彙を正式に網羅したことにはしない。既存のMarkdown一括登録は、引き続き利用できる入口として残す。

## 出題は3段階でつなぐ

| 段階 | 出題例 | 取り出すもの |
| --- | --- | --- |
| 1. やさしく言う | 「状況をさらに悪化させる」を、やさしい英語で | make things worse など |
| 2. 難語に言い換える | make the problem worse を、今回覚える動詞で | exacerbate |
| 3. 文の中で使う | 寝不足が問題をさらに悪化させる場面を、今回の表現で | Lack of sleep can exacerbate the problem. |

最初は、やさしい言い方と難語のつながりを短く紹介する。その後は意味や場面から英語を取り出す。文章段階では、まず文中の難語だけを埋める問題から、全文を思い出す問題へ進める案も考えられる。

同じ文章の暗唱だけを続けず、後の復習で別の場面も混ぜる。たとえば寝不足の文から、渋滞や大雨が状況を悪化させる文へ変える。読む・聞くときに難語を理解する課題も別に残し、英検向けの認識と産出の両方を扱う。

## 解放と復習の扱い

- やさしい表現を出せたら、難語の段階を少しずつ混ぜる。最初から全セットを難文にせず、次の段階を長期間待たせる設計にも固定しない。
- その場の成功は「次を試せる」、後日の復習でも取り出せた記録は「後日も思い出せた」と分ける。回数・比率・手掛かり条件は試作で調整する。
- やさしい表現・難語・文章には別々のFSRS状態を持たせる。簡単な表現の成功を、難語や文章のGoodへ自動転記しない。
- 練習時の頭文字・文字数・追加ヒントと、手掛かりなしの確認を区別する。解放条件にどの確認を使ったかも残す。
- 復習では別セットを挟み、直前に見たやさしい表現だけで難語を答えた結果を、独立した記憶確認と混同しない。
- 正解ごとの確認画面は増やさず、現在の「どんどん回す」テンポを維持する。

やさしい表現は、難語より文字数が多くなる場合がある。語彙の難しさ、文字数、入力速度を同じ指標にしない。現行のコース時間を踏まえ、長い言い換えが入力時間だけで不利にならない出題量・評価方法を検討する。時間設定の変更はこの案だけで実行しない。

## 正解を1通りに狭めすぎない

やさしい言い換えには複数の妥当な回答がある。最初の実装は許容する表現を複数登録し、未登録の別解を追加・編集できる形が現実的。

自由な言い換えを意味で自動判定する機能は別の課題とする。文字列一致で扱える範囲を明示し、未登録の自然な言い方まで、意味が間違っていると断定しない。難語への変換課題では、今回の対象語を使う問題であることを明示する。

## 現行アプリへの実装案

- 現在のカードはprompt・answers・explanationが中心で、セット同士の関係や前提段階は保持していない。任意の親セットID・語義・段階・出題方向を追加する案。
- 新しいセットには安定したIDを付け、段階ごとの子カードIDを用意する。例文の追加だけで、既存の別段階の復習記録を作り直さない。
- 語義や正解そのものが変わる場合は、該当する学習記録への影響を扱う。単なる注釈の編集と分ける。
- 既存の単体カード・Markdownデッキと共存させ、セット登録を利用する人だけが新しい入力画面を使えるようにする。
- 初期検証は少数のセットで、登録の手間、やさしい言い換えの後日産出、対象語の後日産出、別文脈での使用、離脱・ヒント依存を見比べる。

## 根拠と、これから確かめる部分

- **CEFR Companion Volume（2020）、Compensating、冊子p.69**：[欧州評議会の本文PDF](https://rm.coe.int/common-european-framework-of-reference-for-languages-learning-teaching/16809ea0d4#page=69)。言い換えや迂言を、表現が出ないときに意思疎通を保つ方略として扱う。これは「やさしい英語でも伝えられる」という目標との整合であり、上記3段階の順序の効果を証明する実験ではない。
- **産出方向・想起・間隔・手掛かりの限界**：[既存の調査メモ](research/learning-evidence.md)のR1・R3・R4・R9を参照。意味から出すこと、後日確かめること、支援付き成功と独立した想起を分ける方針へつなぐ。
- **例の語義**：[Cambridge Dictionary・exacerbate](https://dictionary.cambridge.org/dictionary/english/exacerbate)。検索結果の辞書説明で語義を確認。本文の直接取得は403だったため、本文を読了したとは扱わない。

「やさしい表現を先に練習すると難語を実用で使いやすくなる」「この解放条件がよい」という部分は、今回試す設計仮説。タイピングだけで自発的な会話力まで測れたとは判断しない。
