# UI：8px基準の余白と学習カレンダー

## 目的

Progateのコース中心の学習体験を参考に、白・ミント・落ち着いた紺色の学習ホームへ整理する。寿司のイラストとゲームの操作感を残し、コース・実際の取り組み・今日の学習量を見やすくする。学習中のテンポは変えず、成果の確認はメニュー・記録・結果へ集める。

## 余白のルール

- 基本単位は8px。主な余白は8 / 16 / 24 / 32 / 40 / 48 / 64px。
- 隣接する小さな要素、凡例、キーボードには4pxを許容する。
- `style.css` の `--space-*` を共有し、padding・margin・gapはトークンで指定する。
- パネル内は24–32px、カード内は16–24px、同じグループの要素間は8–16pxを基本にする。
- フォント、枠線、影、寿司やカレンダーなどのイラストの寸法は別の役割であり、8px倍数には強制しない。皿の215px幅は移動計算と一致させる。
- 通常ボタンは40px以上、主要ボタンと狭い画面の操作領域は高さ48px以上。小さすぎた補足文字を拡大し、薄い文字のコントラストを調整。

## 狭い画面

- 700px以下で学習コースを1列のカードへ変更し、イラストとテキストはグリッドで配置。
- 600px以下ではヘッダーのボタンを独立した1行へ並べ、学習サマリーを縦に整列。
- 同じ幅でコースカードの画像を小さくし、コース開始ボタンはカード幅いっぱいに配置。
- 入力欄・保留・一時停止は十分な高さを確保。画面キーボードは幅に収まる比率で並べる。
- カレンダーはviewBox付きSVGで幅に追従。横スクロールをページ全体へ強制しない。
- 既存の「動きを減らす」設定への対応、フォーカス表示、音OFFを保持する。

これは将来のスマートフォン利用に向けた配置の土台。実機でのキーボード表示やプレイ領域・音の検証は未実施。

## 学習カレンダー

- 日曜始まりの13週間。日付は端末のローカル時刻で集計する。
- 各日の挑戦数を0回／1–4回／5–14回／15–29回／30回以上の5段階で色分け。
- 今日を枠で示し、マウスで日付・内訳を確認可能。SVGには期間の要約ラベルを付ける。
- 日別の詳細は直近7日の表でも読める。カレンダーの色だけを情報源にしない。
- 今日の挑戦、追加ヒントなしの完答、今日または昨日までの連続日数を数字で表示。
- 架空の実績やサンプルの草は入れない。未記録日は淡い色で表示する。

## 保存と検証

日別合計は詳細ログと別に保持し、既存の保存ログから初期化する。再読み込みで二重加算しない。詳細は [学習設計](learning-design.md#v06余白と学習の見える化)。

モデルとDOMで、移行、二重計上の防止、詳細ログから独立した保持、日付境界、連続日数、実績ゼロ、表示の更新を確認。CSSの構文解析と既存ゲームの自動テストも実施。実ブラウザでの視覚・実機操作検証は未実施。

## v0.9：学習ホームとアカウント

[Progateの公開ページ](https://progate.com/)の、段階的なコース・親しみやすいイラスト・学習の道のりを参考にした。画像・キャラクター・ロゴは流用せず、既存の寿司イラストを使用する。`learning.css`で白背景・ミントの操作色・青系の本文・余白のあるカードへ統一。

ホームに単語・熟語・例文のカード、取り組んだ問題数、今日の挑戦、復習待ち、連続日数を表示する。未着手は0のまま表示し、取り組みを習得済みとは呼ばない。カードから直接開始できる。ログイン・登録・再設定は同じ配色のダイアログへまとめ、ゲーム中に開くと従来どおり一時停止する。

Google・メールのボタンは実際のSupabase Authへ接続。接続設定がない場合は準備中と表示し、成功を模擬しない。Supabase側のGoogle・SMTP・テーブル設定は別途必要。ブラウザQAツールがないため、見た目の実機確認は未実施。
